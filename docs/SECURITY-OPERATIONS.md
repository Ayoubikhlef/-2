# تشغيل الأمان: النسخ الاحتياطي والمراقبة

هذا الملف يشرح الإعدادات التشغيلية فقط. لا تضع أي مفتاح أو كلمة مرور أو رابط قاعدة بيانات داخل المستودع.

## 1. النسخ الاحتياطي المشفّر

### كيف يعمل

- يقرأ الخادم كل جداول PostgreSQL عبر Prisma، ويحوّلها إلى JSON، ثم يضغطها ويشفّرها بـ AES-256-GCM.
- المفتاح (`BACKUP_ENCRYPTION_KEY`) يبقى في متغيرات بيئة الخادم ولا يُعاد أبدًا في أي واجهة.
- يمكن تنزيل نسخة يدويًا من **لوحة الإدارة ← الأمان ← النسخ الاحتياطي المشفّر**.
- عند تفعيل الجدولة، تُحفظ النسخة تلقائيًا مرة يوميًا في مستودع GitHub خاص، أو على قرص الخادم إن لم يُضبط GitHub.
- ملف النسخة يحتوي على بيانات العملاء وبصمات كلمات المرور، لكنه مشفّر. احفظه في مكان آمن، ولا تشاركه.

> Render Free لا يوفّر نسخًا احتياطية مُدارة لقاعدة البيانات. النسخ التطبيقية هذه هي خط الدفاع الأساسي، ويجب أن تُخزّن خارج الخادم (GitHub خاص أو جهاز المالك). قرص Render Free مؤقت ويزول مع إعادة النشر.

### الإعداد في Render

1. أنشئ مفتاحًا عشوائيًا (64 حرفًا افتراضيًا، والحد الأدنى 32):

   ```bash
   cd server
   npm run backup:key
   # بطول مخصص (32 حتى 128):
   npm run backup:key -- --length 48
   ```

   احفظه في مدير كلمات المرور. إذا فُقد المفتاح فلن يمكن فك أي نسخة مشفّرة به.

2. أضف في Render ← خدمة `aos-api` ← Environment:

   | المتغير | القيمة |
   |---|---|
   | `BACKUP_ENCRYPTION_KEY` | المفتاح الذي أنشأته |
   | `BACKUP_AUTO` | `true` لتفعيل النسخ اليومي |
   | `BACKUP_HOUR_UTC` | ساعة التنفيذ بتوقيت UTC، افتراضيًا `3` |

3. أعد تشغيل الخدمة. ستظهر حالة التشفير والجدولة في لوحة الإدارة.

### الحفظ خارج الخادم عبر GitHub خاص (موصى به)

1. أنشئ مستودعًا **خاصًا** جديدًا للنسخ، مثل `aos-backups`.
2. أنشئ Fine-grained personal access token من GitHub، وامنحه صلاحية **Contents: Read and write** على هذا المستودع فقط.
3. أضف في Render:

   | المتغير | القيمة |
   |---|---|
   | `BACKUP_GITHUB_REPO` | `owner/aos-backups` |
   | `BACKUP_GITHUB_TOKEN` | التوكن الخاص |
   | `BACKUP_GITHUB_PATH` | `backups` (اختياري) |
   | `BACKUP_GITHUB_BRANCH` | فرع المستودع إن لم يكن الافتراضي |

4. أبقِ `BACKUP_AUTO=false` حتى تتأكد من نجاح أول نسخة يدوية.

### فحص نسخة واستعادتها

من جهاز المالك، مع تعيين `BACKUP_ENCRYPTION_KEY` في البيئة:

```bash
cd server
npx tsx scripts/backup-tool.ts inspect  <backup.enc>
npx tsx scripts/backup-tool.ts decrypt  <backup.enc> <backup.json>
```

الاستعادة **مدمّرة**: تستبدل كل الجداول الموجودة في النسخة. جرّبها أولًا على قاعدة Staging:

```bash
DATABASE_URL="postgresql://..." \
  npx tsx scripts/backup-tool.ts restore <backup.enc> --yes --dry-run

DATABASE_URL="postgresql://..." \
  npx tsx scripts/backup-tool.ts restore <backup.enc> --yes
```

- `--dry-run` يطبع ترتيب الجداول وعدد الصفوف دون تعديل قاعدة البيانات.
- الاستعادة تستخدم `jsonb_populate_record` داخل معاملة واحدة، وتُرجع أي فشل بالكامل.
- إذا كانت قاعدة الهدف جديدة، شغّل `npx prisma db push` أولًا لإنشاء الجداول.
- بعد الاستعادة، احذف ملف JSON غير المشفّر من الجهاز.

### دورة المفاتيح

- المفتاح الجديد يشفّر النسخ الجديدة فقط. احتفظ بالمفاتيح القديمة إلى أن تنتهي صلاحية النسخ القديمة.
- لا تضع المفتاح في Git أو في تقرير أو في لقطة شاشة.

## 2. المراقبة والتنبيهات

### المراقبة الخارجية

ملف `.github/workflows/keep-api-warm.yml` يعمل كل 5 دقائق ويقوم بما يلي:

- فحص `https://aos-tech.store/api/health` (يعيد 503 إذا فشلت قاعدة البيانات).
- فحص الصفحة الرئيسية `200`.
- فحص تحويل `www` و`http` إلى `https://aos-tech.store/` (`308`).
- فتح Issue واحد بعنوان `aos-tech.store health check failing` عند الفشل.
- إغلاق الـIssue تلقائيًا بعد أول فحص ناجح.

GitHub يرسل بريدًا إلى مالك المستودع عند فشل التشغيل. لا تحذف الـIssue يدويًا؛ أغلقه بعد الإصلاح أو اتركه يُغلق تلقائيًا.

### تنبيهات الأمان

- تُسجّل محاولات الاختراق في `AuditLog` وتظهر في **لوحة الإدارة ← الأمان**.
- التنبيهات الفورية تُرسل عبر Telegram أو Discord أو Resend/SMTP عند ضبط متغيراتها في Render.
- زر **تنبيه تجريبي** في لوحة الأمان يتحقق من القناة.
- الحظر التلقائي يعمل بعد تكرار الحوادث؛ استخدم `/api/auth/unblock` مع `ADMIN_GATE_CODE` لفك حظر IP المالك.

### مراجعة دورية مقترحة

- أسبوعيًا: تأكد من وجود نسخة احتياطية حديثة في الوجهة الخارجية.
- شهريًا: نزّل نسخة، شغّل `inspect`، ثم استعدها على Staging وتحقق من عدد الطلبات والمستخدمين.
- ربع سنويًا: راجع التنبيهات المسجلة، وأزل أي عناوين IP قديمة، وحدّث التبعيات.

## 3. مخاطر متبقية مقبولة مؤقتًا

- **Prisma 6 CLI**: تنبيهات `npm audit` المتبقية تخص أدوات CLI/build (`prisma`, `@prisma/config`, `deepmerge-ts`) وليست مسارًا لمدخلات المستخدم في وقت التشغيل. الترقية إلى Prisma 7 تغيير رئيسي وتحتاج جلسة ترحيل منفصلة.
- **@xenova/transformers**: سلسلة `onnxruntime`/`protobufjs`/`sharp` تُحمّل نموذج البحث الدلالي الثابت عند الإقلاع. لا يوجد نموذج أو رابط يتحكم به المستخدم. إزالتها تلغي البحث الدلالي، لذا تُراجع عند توفر بديل مدعوم.
- **Render Free**: لا يوفّر نسخًا مُدارة لقاعدة البيانات، والقرص مؤقت. الاعتماد على النسخ المشفّرة والوجهة الخارجية إلزامي، مع اختبار استعادة دوري.
