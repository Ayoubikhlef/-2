## 🚀 Next Steps (Required!)

### Step 1: Create Sentry Account & Project

1. Go to https://sentry.io/dashboard/
2. Click "Sign up" and create a free account
3. Once logged in, click "New project"
4. Select **Next.js** app type
5. Name it (e.g., `aostech-store`)
6. Copy the **Client DSN** to your clipboard

### Step 2: Get Auth Token for Source Maps

1. Go to https://sentry.io/account/auth-tokens/
2. Click "New access token"
3. Name it (e.g., `aos-tech-store-sm-upload`)
4. Grant **"Write"** permissions
5. Copy and store the token securely

### Step 3: Configure Environment Variables

Edit `server/.env.sentry-local`:

```bash
# Replace with your actual DSN from Step 1
SENTRY_DSN="https://your-public-key@sentry.io/project-id"

# Add auth token from Step 2 (for source map uploads)
SENTRY_AUTH_TOKEN="your-auth-token-here"

# Optional: Organization name
SENTRY_ORG="aostech-store"

# Project name (default works fine)
SENTRY_PROJECT="nextjs"
```

### Step 4: Build the Application

```bash
npm run build
```

This will automatically run the Sentry wizard which uploads source maps to Sentry.

### Step 5: Verify Integration

Start development server:

```bash
npm run dev
```

Visit http://localhost:5173/sentry-status

Expected output (green checkmark):
- ✅ Sentry is properly initialized
- ✅ Configuration status shown
- 🔗 API connection status

## 💡 Usage Examples

### Manual Error Capture

```typescript
import { captureError } from '@/lib/capture-error';

try {
  await someAsyncOperation();
} catch (error) {
  await captureError(error, {
    userId: user.id,
    routeName: window.location.pathname,
  });
}
```

### Performance Tracking

```typescript
import { capturePerformance } from '@/lib/capture-error';
```

## 🔒 Security Considerations

### ⚠️ Important Notes:

1. **Never commit `.env.sentry-local`** with real values to version control
2. The `/api/errors` route is development-only for tunnel mode
3. Production uses Sentry's native error handling (no manual tunneling)
4. Sensitive data should not be logged by your application

### ✅ Best Practices:

- Use `SENTRY_MASK_ALL_INPUTS=true` in production to mask form inputs
- Regularly review errors in Sentry dashboard
- Set up alerting rules (email, Slack) in Sentry project settings
- Enable source map uploads for production builds

## 🛠️ Troubleshooting

### Errors not appearing in Sentry?

1. ✅ Verify `SENTRY_DSN` is set correctly in `.env` or `.env.local`
2. ✅ Check DSN URL matches your Sentry project exactly
3. ✅ Open browser console - check for Sentry SDK initialization warnings
4. ✅ Ensure production build (source maps required)
5. ✅ Visit `/sentry-status` to verify configuration

### Source maps not uploading?

1. ✅ Get auth token from https://sentry.io/account/auth-tokens/
2. ✅ Add `SENTRY_AUTH_TOKEN` to `.env.sentry-local` and `.env`
3. ✅ Rebuild: `npm run build`
4. ✅ Check Sentry dashboard → Settings → Source Code → Organizations

### Adjusting Performance Monitoring?

Edit `server/.env`:

```bash
# Change from 20% sampling
SENTRY_TRACES_SAMPLE_RATE="0.5"  # Sample 50%
SENTRY_ORG="your-org"
SENTRY_PROJECT="aostech-store"
```

### Disable Session Replay?

Add to `server/.env`:

```bash
SENTRY_MASK_ALL_INPUTS="false"
```
